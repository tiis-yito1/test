# Code Reviewer

コードレビューの観点と深さを定義するスキル。
AI のセルフレビュー・レビュー支援、および人間レビュアーの共通基準として使用する。

---

## レビュー観点チェックリスト

レビュー時に以下の観点を順に確認する。
コーディング規約（命名、可読性、ネスト制限等）のチェックは `sdd-implementer` Skill の Coding Standards を参照すること。

### 1. アーキテクチャ準拠

- レイヤー間の依存方向が正しいか（Presentation → Application → Domain、Infrastructure は外側）。
- 循環参照が発生していないか。
- `docs/02_architecture/アーキテクチャ.md` に定義されたディレクトリ構造に従っているか。

### 2. 仕様との整合性

- Tier 2 仕様書 (`docs/03_features/{FeatureName}/仕様.md`) の要件を満たしているか。
- Tier 1 (`docs/02_architecture/`, `docs/01_product/用語集.md`) に違反していないか。
- 仕様に記載のない振る舞いを勝手に追加していないか。

### 3. 用語集準拠

- 変数名・クラス名・API パス等が `docs/01_product/用語集.md` の用語と一致しているか。
- 独自の訳語や略語を作っていないか。

### 4. セキュリティ

- 認証・認可チェックが適切か（RBAC: Admin vs User の権限マトリクス準拠）。
- API エンドポイントにフロントエンドの非表示だけでなくサーバーサイドのアクセス制御があるか。
- 外部入力（Slack メッセージ等）の表示時に XSS 対策（サニタイズ）がされているか。
- 機密情報（API キー、パスワード）がハードコードされていないか。

### 5. エラーハンドリング

- Fail Fast の原則に従い、安易なデフォルト値で異常を隠蔽していないか。
- プロジェクト内の既存エラー定義（Error クラス、Result 型）を使用しているか。
- エラーメッセージが「何が問題で、どうすれば解決できるか」を伝える具体的な内容か。

### 6. テストの十分性

- 正常系・異常系・境界値のテストケースが網羅されているか。
- テストが仕様（Tier 2）のシナリオに対応しているか。
- モック境界が適切か（詳細は `test-strategy` Skill を参照）。

### 7. パフォーマンス

- N+1 クエリが発生していないか（EF Core の Include/ThenInclude の確認）。
- フロントエンドで不要な再レンダリングが発生していないか。
- API 応答が 95 パーセンタイル 200ms 以内の目標を達成できる設計か。

## レビューの深さ

変更の種類に応じてレビューの深さを使い分ける。

### Spot Check（軽微な変更）

- 対象: typo 修正、コメント修正、ドキュメント更新、フォーマット修正。
- 確認: 変更が意図通りか、副作用がないか。

### Standard（通常の機能追加・修正）

- 対象: 機能追加、バグ修正、リファクタリング。
- 確認: 上記チェックリストの全項目。

### Deep（高リスクな変更）

- 対象: セキュリティ関連、DB スキーマ変更、破壊的 API 変更、認証・認可ロジック。
- 確認: 上記チェックリストの全項目に加えて以下を実施。
  - 既存テストの影響範囲を確認し、不足があれば追加テストを提案。
  - マイグレーションの可逆性（ロールバック可能か）を確認。
  - 本番データへの影響を評価。

## スタック固有の注意点

### .NET (Backend)

- `DateTime.Now` の使用禁止。`DateTime.UtcNow` を使用すること（`docs/03_features/共通仕様.md` §4 準拠）。
- FluentValidation ルールがエンティティの制約と一致しているか。
- EF Core クエリの効率性（不要な全件取得、N+1、未使用カラムの SELECT）。
- `async/await` の適切な使用（同期ブロッキングの回避）。

### Next.js (Frontend)

- Server Component と Client Component の使い分けが適切か。
- 日時表示で `timeZone: 'Asia/Tokyo'` が明示的に指定されているか。
- `useEffect` の依存配列が正しいか。
- 画像の最適化（`next/image` の使用）。

### Slack (Service)

- `event_id` / `SlackMessageId` による冪等性が担保されているか。
- Slack API の Rate Limit を考慮した設計になっているか。
- Socket Mode 接続のエラーハンドリングと再接続ロジック。
