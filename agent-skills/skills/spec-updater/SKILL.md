# 仕様書更新スキル

このスキルは、議事録や仕様変更書などのドキュメントをインプットとして、既存の仕様書（例：Markdownファイル）を更新する際にエージェントをガイドします。

## ワークフロー

仕様書を正確かつ効率的に更新するために、このワークフローに従ってください。

### 1. インプットを受け付ける

まず、ユーザーから必要な2つのファイルパスを受け付けます。

- **変更要求ドキュメントを尋ねる:** 「変更内容が記載された議事録や仕様変更書のパスを教えてください。」
- **現行の仕様書を尋ねる:** 「更新対象となる、現在の仕様書のパスを教えてください。」

### 2. 変更要求を分析し、要約する

受け取った「変更要求ドキュメント」を読み解き、何を変更すべきかを抽出・要約します。

1.  **分析ガイドを参照する:** まず `references/change-analysis-guide.md` を読み込み、ドキュメントを分析する際の指針を理解します。
2.  **ドキュメントを読み込む:** `read_file()` で変更要求ドキュメントの内容を読み込みます。
3.  **変更点を抽出・整理する:** ガイドに従い、決定事項、変更の対象・内容・理由を抽出します。
4.  **要約してユーザーに確認する:** 抽出した変更点を箇条書きでユーザーに提示し、認識が正しいか確認を取ります。

**対話例:**
> **エージェント:** 「議事録を拝見しました。以下の変更を行うという認識でよろしいでしょうか？
> *   プロジェクト名を「デジ戦ポータル」から「ProjectGENA」に変更
> *   ログイン画面から「パスワードを記憶する」チェックボックスを削除
> *   APIの応答時間目標を300msから200msに短縮
> 」

### 3. レビューのための差分を生成する

ユーザーの確認が取れたら、現行の仕様書への変更案を差分（diff）形式で生成します。

1.  **現行仕様書を読み込む:** `read_file()` で現行の仕様書の内容を読み込みます。
2.  **変更案を生成する:** ステップ2で確認した変更点を基に、仕様書の内容を修正したバージョンを生成します。単純な置換だけでなく、文脈に合った自然な表現になるよう努めます。
3.  **差分を生成する:** 元の仕様書と変更後のバージョンの差分を `diff -u` コマンド等で生成します。

### 4. ユーザーの最終承認のために変更点を提示する

生成された差分をユーザーに提示し、変更をファイルに適用する前の最終承認を求めます。

**対話例:**
> **エージェント:** 「ありがとうございます。現行仕様書への変更案を差分で作成しました。ご確認の上、承認をお願いします。
>
> ```diff
> --- a/spec.md
> +++ b/spec.md
> @@ -10,7 +10,7 @@
>  ## 非機能要件
>  - パフォーマンス: APIの応答時間は **300ms** 以内であること。
> + - パフォーマンス: APIの応答時間は **200ms** 以内であること。
> ```
>
> この内容でファイルを更新してもよろしいですか？」

### 5. 変更を適用する

ユーザーが変更を承認した場合、元の仕様書ファイルを変更後の内容で上書きします。

```bash
write_file(file_path="<path_to_spec_file>", content="<the_full_modified_content>")
```

### 6. 最終確認

変更を書き込んだ後、ファイルが正常に更新されたことをユーザーに伝えます。

> **エージェント:** 「仕様書ファイルを更新しました。」
